Why this tab exists. PS, DS, PPG and SC are nominal categories — there is no established theoretical ordering between them, so treating a PPG↔SC mismatch as "smaller" than a PS↔SC mismatch (as an ordinal-weighted kappa would) is not justified. The primary statistic is therefore standard, unweighted Cohen's kappa (shown in the Chunk-matched agreement tab), which treats every mismatch equally. This tab is a separate, clearly-labeled alternative: instead of assuming any fixed relationship between categories, it asks a chunk-specific question — for THIS chunk, was the AI's pick at least the human's own secondary (runner-up) emphasis, or vice versa? That "vicinity" is defined independently for every chunk from each coder's own point ranking on that chunk, never from a global category order.

Observed vs. chance: strict vs. flexible match

How the chance line is computed: within this selection, AI chunks are randomly re-paired against human chunks thousands of times (holding each side's own chunk-level data fixed), and the match rate is recomputed each time. The average over permutations is the chance baseline — a Monte Carlo analogue of Cohen's Pe, since the flexible-match criterion uses both coders' per-chunk rankings and has no closed-form chance formula. As a built-in check, the same permutation applied to strict (standard) matching should closely reproduce the closed-form standard kappa above — it does (see the readout below).

Overall logic frequency — every chunk either coder coded

This uses every chunk the human coder marked applicable, and separately every chunk the AI pipeline marked applicable — not just the subset where both coders happened to code the same chunk. It answers "what did each coder find across the whole report," independent of whether their chunks line up 1:1. Compare this to the chunk-matched view: a report can show similar overall logic mixes here while still disagreeing chunk-by-chunk, or vice versa.
